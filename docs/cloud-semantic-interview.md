# 云端语义追问 + 本地语音

现已接入第一版语义追问。语音仍使用本机 SenseVoice/CosyVoice；最终回答、简历及相关上下文
发送给用户指定的云端兼容 API，由模型分析并决定追问。没有安装或启动本地 LLM。

## 使用

- 普通页面与 LiveKit 页面均提供“云端语义追问 / 离线规则练习”选择。
- 云端模式填写 API Base、Model、API Key；当前支持 `/v1/chat/completions` 风格兼容服务。
  Anthropic 原生 Messages 等不同协议尚未接入，不应填到兼容接口后假定一定可用。
- LiveKit 页面云端设置仅保存在页面内存，服务商 Key 只传给本机 API，不进入房间 token 或 Agent 调度元数据。
- 普通页面延续原有浏览器 localStorage 保存设置的行为。后端 SQLite 中的 Key 仍脱敏。
- 默认只对最终回答调用云端模型。中间 ASR 留在本机；语义会话禁用规则版的云端预判/音频预备，
  避免每个转录快照都收费或泄露临时回答。因此此前约一秒的规则版成绩不能沿用。

API 创建面试时使用 `interview_strategy: "semantic"`；旧客户端省略字段仍走 `rules`。
`provider_config.llm` 必须有云端兼容 provider、api_base、model、api_key。
云端超时、非 JSON、引文无效、跨工作流输出等会返回错误，保留当前轮次；不会悄悄切回模板追问。

## 八股与项目的区别

八股上下文带当前题目的知识卡、参考 rubric、来源、已问问题和知识理解记录。
模型区分正确、遗漏、错误与不确定，再选择澄清、继续验证或换目标。
错误判定需要引用提供的知识卡；卡片不足时应先澄清，而不是虚构依据。

项目上下文带简历和候选人的原话，以及分项目标记的陈述台账。
重点是本人职责、业务约束、实施细节、选型取舍、指标归因和复盘。
记录只能表示候选人自述、待澄清或前后冲突，不能把一段自述标记成已独立验证。
项目名与引文需要来自给定材料；不能用通用知识卡证明候选人做过某件事。

工作流分别使用提示词、状态字段和评价尺度，可共用同一个云端模型。
回答次数与阶段游标已分开，同一目标可连续追问；模型选择 advance 或达到每目标四轮预算后换目标。
主问题仍可以来自题库，针对回答的追问由云端模型决定。

## 输出校验、状态和报告

- Pydantic 校验 JSON 决策，限制工作流、动作、状态与长度。
- 必须引用本轮回答，quote 必须逐字存在于对应来源。
- 检查知识来源 ID、项目身份、未知指标、重复问题和明确的假设标记。
- 在会话副本上完成决策，只有持久化成功后替换热缓存，防止失败吃掉一轮回答。
- 每轮保存语义状态快照和下一题；重启后恢复相同问题与状态，不重新猜测阶段。
- 服务商 Key 仅存于进程内存。重启后若需继续回答，可重新调用
  `POST /v1/interviews/{id}/llm`，body 为 LLM provider 设置；历史报告不需要重新调用云端。
- 使用模型返回的独立评价，不再用关键词/长度的旧分数冒充语义评分。
  uncertain 回答 score=null，不参与均分；报告标注“模型辅助判断、未经人工校准”。

这些校验不能自动证明所有语义判断正确。项目陈述是否真实、问题是否足够深入、评分是否公平，
仍需要真实模型的对照测试和人工审核。当前知识卡也尚未全部升级为完整、版本化的技术证据库。

## 多轮效果测试

已准备两个合成候选人场景，每个默认四轮：

1. 八股：先把 equals/hashCode 关系说错，随后根据追问纠正，测试是否继续验证可变 key 的边界。
2. 项目：索引优化与缓存同时上线；本人不负责缓存，测试是否追问归因、尊重职责边界、避免串项目。

在本机复制 `configs/llm.local.example.json` 为 `configs/llm.local.json`，填入可用云端配置，运行：

```powershell
$env:PYTHONPATH = "$PWD\apps\api"
python scripts/evaluate_semantic_interview.py --config configs/llm.local.json --rounds 4
```

也支持 `OPENINTERVIEW_LLM_API_BASE` / `OPENINTERVIEW_LLM_MODEL` / `OPENINTERVIEW_LLM_API_KEY`。
运行会真实调用云端并可能产生费用，仅发送脚本中的虚构材料。
输出 `logs/semantic-interview-evaluation.json` 包含实际问题、候选人回答、决策、引用、延迟与最终状态。
连接/格式/校验失败标为 invalid_run；完成运行不等于面试质量合格，不用模型自打分代替人工评审。

当前验证了接口、状态、证据约束和模拟响应回归；**尚未完成真实云端拟真对话评测**。
本次环境中的既有服务配置在 TLS 阶段连接失败，且没有指定模型名，不能据此声称模型效果通过。
