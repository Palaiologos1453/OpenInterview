# 本地语音流水线：增量反馈与可撤销准备

这次优化面向模拟面试官：用户说话时提前识别、预判下一步；最终回答确认前不推进题目、不写评分、
不播放预测的追问。没有新增云端服务、LLM 或 RAG，仍使用本机 SenseVoice、规则引擎和 CosyVoice。

## 已实现

1. **说话中更新转录**：LiveKit 自定义 STT 适配器用 Silero VAD 维护语段，前 20 秒内每约 1.2 秒
   对累计语音做一次 SenseVoice 快照识别。中间文本可被修正，页面明确标注“识别中（可能修正）”。
   这是批量模型的增量封装，不是原生流式解码，也没有复用 ASR decoder cache。
2. **背压与版本隔离**：每条流最多一个快照请求，慢请求期间跳过快照，不排队补算；语段结束后
   丢弃晚到的中间结果，完整语段识别才是最终文本。长回答停止快照，但仍保留最终完整语段识别
   （当前 VAD 缓冲上限 120 秒）。同一个 FunASR 模型的推理串行保护，防止并发修改内部状态。
3. **只读预判**：`POST /v1/interviews/{id}/preview` 检查轮次后复制会话，再在副本上运行规则引擎。
   不写 turns、分数、报告或正式会话。最终 `/turn` 仍重新按完整回答计算，已有幂等逻辑保留。
4. **预备音频**：两个快照都预测到同一道题，才开始一份 CosyVoice 合成。每轮最多尝试一次，
   未确认的缓存最多 30 秒 PCM。最终题目全文和预期轮次完全匹配才取用；修正回答引起题目变化、
   状态过期、合成失败或缓存超限，都丢弃预测结果并走正常生成路径。
5. **控制口头提问长度**：语音只读题目第一行的主问题，不连读后面的“追问方向”。屏幕仍展示
   完整题目。这样被打断的长播报更快释放 TTS worker，提前合成才有机会真正运行。
6. **记录正确的时间点**：冒烟测试现在在 `data_received` 回调记录题目事件时间，在音频回调记录
   非静音音频到达时间。旧脚本在注入两秒静音后才读时钟，会把题目事件延迟测成至少约两秒，
   因而旧的文本事件指标不能直接与这次比较。

中间 ASR 使用 `persist=false`，不把每个快照写入转录/trace。最终回答仍入库。UI 文本更新不是
“模型已经生成了有用答案”，要分别看转录反馈延迟和下一题可听音频延迟。

## 本机对照结果

2026-10-03，使用同一份本地合成候选人 WAV、同一岗位/模式、VAD 阈值、声音配置和 WebRTC
客户端。模型提前预热；候选人在开场题播报期间插话，验证这一常见的队列竞争场景。

| 条件 | 说完到下一题音频到达（两次） | 说话中转录 |
| --- | --- | --- |
| 主问题播报；关闭增量识别和预备合成 | 3.09 秒、3.43 秒 | 无 |
| 主问题播报；开启增量识别和预备合成 | 1.05 秒、1.01 秒 | 约 1.5 秒出现首段，每次结束前更新 5 次 |

这组样本平均等待从 3.26 秒降到 1.03 秒，约减少 **68%**。两次预测都匹配最终题目。
实际声卡/扬声器播放还会增加缓冲时间；这不是测量物理出声时间。

最初保留整段“题目 + 追问方向”播报时，关闭优化两次为 5.48/7.30 秒，开启三次为
3.78/6.74/5.50 秒，收益不稳定。不能把所有收益归因于并行，也不能把“预测命中”当作音频已就绪。
旧 TTS 仍需完成计算，长播报会阻塞后续合成；减少口头播报长度与提前准备共同改善了体验。

原始记录：[voice-pipeline-2026-10-03.json](benchmarks/voice-pipeline-2026-10-03.json)。
样本量小、只测一个合成回答，TTS 输出有随机波动，没有充分交错随机化，不报告 P95，
不声称已达到 GPT Voice 水准或所有场景都能一秒回应。Redis/MySQL 仍存在识别错误。

## 对照开关与复现

在启动脚本前设置环境变量，重启 Agent 后生效：

```powershell
$env:OPENINTERVIEW_INCREMENTAL_ASR = "0"  # 关闭中间快照，恢复 VAD 后整段识别
$env:OPENINTERVIEW_VOICE_PREFETCH = "0"   # 关闭只读预判及预备音频
.\scripts\start-livekit.ps1 -DatabasePath "$PWD\logs\pipeline-test.sqlite"
.\apps\livekit\.venv\Scripts\python.exe scripts/smoke_livekit.py --reuse-fixture --output logs/livekit/control.json
```

两个开关默认均为 `1`。也可以只关闭预备音频，以观察 GPU 竞争开销。复测时保留
`logs/livekit/candidate.wav`，使用 `--reuse-fixture`，避免更换输入录音。

回归测试覆盖：中间转录早于语段结束、晚到结果作废、慢 ASR 不排队、预判不推进状态、
最终回答改题时不播放旧音频、轮次不匹配与缓存预算、正式提交仍只写入一条记录。

## 下一步

使用真人技术面试录音做更大规模的交错对照，统计端点误判、完整转录、术语错误、预测命中率、
额外 GPU 耗时和实际播放 P50/P95。再决定是否引入原生流式 Paraformer 等本地 ASR，
以及中文语义端点模型。VAD 只能检测声音活动，不能仅凭 200ms 静音判断技术回答已经结束。
预备失败会浪费合成计算，缓存未命中也可能增加排队时间；低显存或慢设备可以关闭预备音频。
